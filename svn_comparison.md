### 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

Разница обусловлена архитектурой хранения данных:

*   **Git (дешёвое):** В Git ветка — это всего лишь **указатель (ссылка)** на определённый коммит (по сути, файл размером 41 байт, содержащий хеш). Создание ветки не копирует файлы, а просто создаёт новую ссылку на существующий снимок состояния. Переключение между ветками также происходит мгновенно, так как Git просто меняет указатель HEAD и разворачивает файлы из объекта коммита.
*   **SVN (дорогое):** В SVN ветка — это **физическая копия директории** в репозитории (через механизм `svn copy`). Хотя SVN использует «ленивое копирование» (copy-on-write) на уровне файловой системы сервера, с точки зрения клиента и истории это полноценная новая ветка. Создание ветки требует операции на сервере, а переключение (switch) может быть медленным, так как требует передачи данных по сети.

### 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет, в классическом SVN сделать коммит без интернета невозможно.**

*   **Причина:** SVN — это **централизованная** система контроля версий. Все коммиты отправляются напрямую на центральный сервер. У клиента нет локальной истории изменений (кроме рабочей копии). Операция `commit` — это сетевая транзакция, которая должна быть подтверждена сервером.
*   **Исключение:** Существует возможность работать без сети с помощью `svn diff` (сохранить патч), но это не коммит. Также есть режим «offline» для некоторых операций (например, `svn status`), но фиксация изменений в истории репозитория требует соединения. (Примечание: в SVN 1.7+ появилась возможность коммитить в *локальную* рабочую копию через `svn commit --depth=empty`, но это не создаёт ревизию в центральном репозитории, пока не будет выполнен `svn update` и `svn commit` на сервер).

### 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

Несмотря на доминирование Git, SVN остаётся удобным в следующих случаях:

1.  **Работа с большими бинарными файлами (GameDev, дизайн):** SVN позволяет хранить большие файлы (текстуры, модели, PSD) без раздувания размера репозитория, так как хранит только изменения (дельты) на сервере. В Git для этого требуется LFS, что сложнее в настройке. Также SVN позволяет делать частичный checkout (только нужную папку), что критично для огромных проектов.
2.  **Жёсткий централизованный контроль:** В корпоративной среде с требованиями безопасности и аудита SVN проще администрировать: есть один сервер, права доступа настраиваются по папкам (path-based authorization), и невозможно «утащить» всю историю на локальную машину (в Git клон содержит всю историю).
3.  **Простые линейные проекты для нетехнических специалистов:** Для художников, дизайнеров или менеджеров, которые работают с файлами, но не знают Git, SVN часто понятнее: «обновил папку — закоммитил». В Git же нужно понимать staging area, ветки и т.д.
4.  **Огромные монолитные репозитории с частичным доступом:** Если нужно дать доступ только к одной папке из 100 ГБ проекта, SVN сделает это легко. В Git придётся либо клонировать всё, либо использовать сложные надстройки (sparse-checkout, partial clone), которые всё ещё менее удобны.
