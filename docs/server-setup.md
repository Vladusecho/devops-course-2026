# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины
- **Оперативная память (RAM):** 2048 МБ (2 ГБ)
- **Количество ядер процессора:** 2 vCPU
- **Объём дискового накопителя:** 25 ГБ, динамически расширяемый
- **Гипервизор:** Oracle VM VirtualBox 7.x
- **Операционная система:** Ubuntu Server 24.04 LTS (ARM 64-bit)

## 2. Сетевые интерфейсы
- **Сетевой адаптер 1 (`enp0s3` / `enp0s8`):**
  - **Тип адаптера:** NAT
  - **Полученный IP-адрес:** `10.0.2.15/24`
  - **Назначение:** Обеспечение исходящего доступа виртуальной машины в сеть Интернет (загрузка и обновление пакетов), а также организация управляющего SSH-доступа через проброс портов гипервизора.
- **Сетевой адаптер 2 (`enp0s8` / `enp0s9`):**
  - **Тип адаптера:** Виртуальная сеть хоста (Host-only Network, `vboxnet0`)
  - **Полученный IP-адрес:** `192.168.56.2/24`
  - **Назначение:** Прямая изолированная сетевая связность между хостовой системой (macOS, IP `192.168.56.1`) и гостевой ОС. Используется для прямого обращения по локальному доменному имени `devops.local` и доступа к веб-серверу в практических работах № 6 и 7.

## 3. Правило проброса портов
- **Наименование правила:** `ssh`
- **Протокол:** TCP
- **Адрес хостовой системы:** `127.0.0.1`
- **Порт хостовой системы:** `2222`
- **Адрес гостевой системы:** (не заполняется / `0.0.0.0`)
- **Порт гостевой системы:** `2222` (перенастроен со стандартного 22 в процессе харденинга службы SSH)

## 4. Учётные записи
- **`student`**:
  - **UID:** 1000
  - **Принадлежность к группам:** `student`, `adm`, `sudo`
  - **Способ аутентификации:** Парольная аутентификация (установлена на этапе инсталляции ОС).
- **`devops`**:
  - **UID:** 1001
  - **Принадлежность к группам:** `devops`, `sudo`, `docker`
  - **Способ аутентификации:** Исключительно по открытому ключу SSH (алгоритм ED25519, открытый ключ размещён в `~/.ssh/authorized_keys`).

## 5. Служба SSH
- **Порт службы:** `2222`
- **Расположение файлов конфигурации:**
  - Базовый файл: `/etc/ssh/sshd_config` (сохранена резервная копия `/etc/ssh/sshd_config.backup`)
  - Файл усиления защиты (hardening): `/etc/ssh/sshd_config.d/99-hardening.conf`
- **Изменённые директивы и их значения:**
  - `Port 2222` — нестандартный порт для минимизации фонового автоматизированного сканирования ботами;
  - `PermitRootLogin no` — запрет прямого входа от имени суперпользователя `root`;
  - `PasswordAuthentication no` — отключение парольной аутентификации в пользу ключевой;
  - `PubkeyAuthentication yes` — разрешение аутентификации по криптографическим ключам;
  - `PermitEmptyPasswords no` — запрет авторизации учетных записей без паролей;
  - `MaxAuthTries 3` — ограничение числа неуспешных попыток авторизации в рамках одной сессии;
  - `LoginGraceTime 30` — ограничение времени на завершение аутентификации (30 секунд);
  - `AllowUsers devops` — ограничение списка пользователей, которым разрешено инициировать SSH-сессию;
  - `X11Forwarding no` — отключение форвардинга графической подсистемы X11;
  - `ClientAliveInterval 300` и `ClientAliveCountMax 2` — контроль тайм-аута неактивных сессий.
- **Особенности конфигурации дистрибутива:**
  - Отключена активация через сокет `systemctl disable --now ssh.socket`, служба переведена на постоянный сервис `systemctl enable --now ssh.service` для корректного применения директивы `Port 2222`.
  - В файле `/etc/ssh/sshd_config.d/50-cloud-init.conf` закомментирована директива `PasswordAuthentication yes`, предотвращая переопределение настроек безопасности.

## 6. Правила межсетевого экрана
- **Политики по умолчанию:**
  - `Default incoming policy`: `deny` (запрещены любые входящие соединения, кроме явно разрешённых);
  - `Default outgoing policy`: `allow` (исходящий трафик сервера не ограничивается);
  - `Routed`: `disabled`.
- **Перечень активных правил (UFW):**
  - `2222/tcp (v4 & v6)` — `LIMIT IN` (входящие подключения SSH с ограничением частоты: не более 6 попыток соединения за 30 секунд);
  - `80/tcp (v4 & v6)` — `ALLOW IN` (HTTP-трафик для веб-сервера);
  - `443/tcp (v4 & v6)` — `ALLOW IN` (HTTPS-трафик для защищённого веб-сервера).

## 7. Снимки состояния
1. **`01-clean-install`** — чистая установка Ubuntu Server 24.04 LTS, первое обновление пакетов системы (`apt update && apt upgrade`) и первичная фиксация сетевых интерфейсов.
2. **`02-keys-configured`** — создана учетная запись `devops`, добавлен в `sudo`, сгенерирована пара ключей ED25519, настроен клиентский алиас в `~/.ssh/config` и проверен вход по ключу без пароля.
3. **`03-ssh-hardened`** — выполнен полный харденинг SSH (отключение root, отключение паролей, смена порта на 2222, отключение сокета `ssh.socket`), обновлён проброс портов в VirtualBox, проверена фиксация отклоненных попыток в системном журнале.
4. **`04-nginx-https`** — установлен Nginx, опубликован статический ресурс `devops-site`, выпущен самоподписанный TLS-сертификат с полем SAN, настроен принудительный редирект HTTP -> HTTPS (код 301) и проверена доступность ресурса.
5. **`05-docker-compose`** — установлен Docker Engine и плагин Compose, собран образ Flask-приложения `devops-app:1.0`, развернут стек «приложение + PostgreSQL» в изолированной сети `backend` с сохранением данных в томе `db_data`.

## 8. Веб-сервер
- **Устанавливаемый пакет:** `nginx` (установлен средствами штатного пакетного менеджера APT: `sudo apt install -y nginx`).
- **Путь к конфигурации ресурса:** `/etc/nginx/sites-available/devops-site` (активирован через создание символической ссылки в `/etc/nginx/sites-enabled/devops-site`; конфигурация по умолчанию `/etc/nginx/sites-enabled/default` отключена).
- **Каталог ресурса, его владелец и права:**
  - Каталог публикации: `/var/www/devops-site`;
  - Владелец каталога и файлов: `devops:devops`;
  - Права доступа: `755` (`drwxr-xr-x`) для каталогов, `644` (`-rw-r--r--`) для файлов. Реализована модель «владелец пишет, веб-сервер читает» (пользователь `www-data` может читать файлы, но лишен прав записи).
- **Пути к сертификату и ключу, их права:**
  - Открытый сертификат: `/etc/ssl/certs/devops.crt`, владелец `root:root`, права доступа `644` (`-rw-r--r--`);
  - Закрытый ключ: `/etc/ssl/private/devops.key`, владелец `root:root`, права доступа `600` (`-rw-------`). Читается главным процессом Nginx (master), запускаемым от имени root, до создания рабочих процессов.
- **Команда формирования сертификата:**
  ```bash
  sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/ssl/private/devops.key \
    -out /etc/ssl/certs/devops.crt \
    -subj "/CN=devops.local" \
    -addext "subjectAltName=DNS:devops.local"
  ```
- **Срок действия сертификата:** 365 дней (1 календарный год).
- **Схема перенаправления и протоколы:**
  - HTTP (порт 80): принудительный постоянный редирект на HTTPS с кодом `301 Moved Permanently` (`return 301 https://$host$request_uri;`);
  - HTTPS (порт 443): шифрование с поддержкой протоколов `TLSv1.2` и `TLSv1.3`.

## 9. Контейнеризация
- **Способ установки Docker Engine и его версия:** официальный репозиторий Docker (APT: `download.docker.com/linux/ubuntu`), установлены пакеты `docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-buildx-plugin`, `docker-compose-plugin`.
- **Участники группы docker:** пользователь `devops` (позволяет выполнять запуск контейнеров и управление стеком без повышения прав через `sudo`).
- **Расположение проекта на сервере:** `/home/devops/app` (файлы `Dockerfile`, `docker-compose.yml`, `requirements.txt`, `app.py`, `.env`).
- **Расположение файла `.env` и его права:** `/home/devops/app/.env`, права доступа `600` (`-rw-------`), владелец `devops:devops`. Содержит чувствительные учетные данные базы данных (переменные `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `DB_HOST`), файл исключен из Git через `.gitignore`.
- **Публикуемые порты и адреса:**
  - Приложение: `127.0.0.1:5000:5000` (порт привязан строго к интерфейсу обратной петли `127.0.0.1` для предотвращения обхода фаервола UFW и исключения прямого несанкционированного доступа из внешней сети);
  - СУБД PostgreSQL: порт `5432` во внешнюю сеть хоста не публикуется, доступ предоставляется исключительно внутри изолированной сети Docker bridge `backend`.
- **Именованные тома:** `app_db_data` (смонтирован в каталог СУБД `/var/lib/postgresql/data` для долговременного сохранения состояния базы данных при перезапуске или пересоздании контейнеров).
- **Конфигурация обратного прокси-сервера:**
  В конфигурационном файле `/etc/nginx/sites-available/devops-site` в секции HTTPS настроен блок обратного проксирования:
  ```nginx
  location /app/ {
      proxy_pass http://127.0.0.1:5000/;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
  }
  ```
  Завершающий слэш в директиве `proxy_pass` обеспечивает перезапись URI, заменяя префикс `/app/` на `/` при обращении к бэкенду.
